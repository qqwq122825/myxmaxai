# 0.4.8：修复本地选 1080P、摄像头仍为 720P

## 原因

0.4.7 本地端在接收连接建立时保存一份视频设置。之后在下拉框改为 1080P，没有触发虚拟摄像头重新配置；连接中启动摄像头也仍使用那份旧设置。本次本机诊断读到 HKCU\Software\FaceLive\VirtualCam 的 Width / Height 为 720 / 1280，与截图中显示的 1080P 选择不同。

因此不能只根据下拉框文字判断实际输出尺寸，也不能据此认定直播伴侣本身不支持 1080p。

## 修复

- 「只接收（手机推流）」模式中更改画面尺寸，会应用到本地虚拟摄像头，不中断接收连接。
- 启动虚拟摄像头始终读取当前输出选择，避免旧连接的 720P 设置覆盖新选择。
- 状态显示摄像头配置的宽高和 FPS。摄像头已经打开时切换尺寸，会提示重开直播伴侣的摄像头。
- 更改 FPS 后按回车或移出输入框，会应用接收模式的输出设置。
- 本机摄像头上传模式保留原有协商尺寸；上传尺寸/帧率更改仍需停止并重新启动推送。
- 镜像与启停状态在输出重新配置时保留。

## 更新与操作

1. 关闭旧本地端，用针对完整 0.4.7 的本地修复包合并覆盖原 RemoteGpu 目录。
2. 运行 RemoteGpuLocal.exe，确认标题 **0.4.8**。服务器 0.4.7 不必更新。
3. 手机推流时，本地选择「只接收（手机推流）」和「1080P 竖屏 · 1080×1920」，启动接收及虚拟摄像头。
4. 确认输出状态显示 **1080×1920**。
5. **重新打开直播伴侣**，编辑原有 FaceLive Camera 素材并检查分辨率。已经打开的设备连接或能力列表可能保留旧尺寸；重配桥接端并不能强制第三方软件刷新已经建立的捕获连接。不要重复添加第二路占用同一摄像头。
6. 如重开后仍仅列出 720P，先关闭直播伴侣，用「检查输出」确认读回尺寸；再查看安装报告里的本地驱动路径。状态显示的是桥接配置尺寸，读回尺寸和直播伴侣协商尺寸仍需分别核对。

0.4.7 临时操作顺序：停止接收、关闭虚拟摄像头、选 1080P、重新启动接收和虚拟摄像头，最后重开直播伴侣。

## 验证

Tk 回归检查使用真实 UnityCamera 初始化路径、独立共享内存命名和模拟注册表，复现活动接收中从 720×1280 切到 1080×1920，验证驱动首选尺寸写入、设置保存、关闭重启后尺寸、横屏 1920×1080 及上传模式不被中途改动。没有改写本机用户的真实摄像头注册表，未操作直播伴侣场景。最终协商尺寸仍需用户在该机重开摄像头验收。
