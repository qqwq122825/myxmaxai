# 15 手机局域网推流（二维码 / Wi‑Fi 模式）

手机 App「AI魔颜」新增 **局域网 Wi‑Fi** 模式：手机和电脑连同一个路由器，手机直接把摄像头画面推给电脑上的「局域网接收端」，不经过公网服务器。

```
iPhone 摄像头 ──H.264（同一 Wi‑Fi）──▶ 电脑局域网接收端 ──▶ 虚拟摄像头 / 换脸软件 / 直播伴侣
```

## 手机端（已完成）

- 面板顶部切换「远程服务器 / 局域网 Wi‑Fi」，两种模式各自记住地址和 Key。
- 地址栏右边是**扫码按钮**：扫描接收端显示的二维码后自动填好地址和 Key，并立即连接；也可以「从相册识别」二维码截图。
- 用系统相机扫码同样可以：二维码是 `aimoyan://` 链接，会直接打开 App 并连接。
- 二维码里有多个地址时（电脑有多块网卡），按顺序尝试，第一个连得上的生效（每个地址最多等 5 秒）。
- 局域网码率更高：720p 6 Mbps、1080p 12 Mbps（远程模式仍是 4 / 8 Mbps）。
- 手机没连 Wi‑Fi 时直接提示；连接失败时提示检查「本地网络」权限、同一 Wi‑Fi、防火墙。
- 首次连接时 iOS 会弹「查找并连接到本地网络上的设备」，必须点**允许**。

## 二维码格式

```
aimoyan://connect?v=1&mode=lan&addr=192.168.1.23:8766,10.0.0.5:8766&key=RGK1.xxxx&name=%E5%B7%A5%E4%BD%9C%E5%AE%A4%E7%94%B5%E8%84%91
```

| 参数 | 说明 |
|---|---|
| `v` | 格式版本，目前为 1 |
| `mode` | `lan`（局域网接收端）或 `remote`（远程服务器也可以显示同样的二维码） |
| `addr` | 一个或多个 `IP:端口`，英文逗号分隔，按优先级排列 |
| `key` | 与手动复制的一样的 `RGK1.` Key（证书指纹 + 访问口令） |
| `name` | 可选，显示名称，需 URL 编码 |

二维码内容如果只是 `RGK1.xxxx`，App 只填入 Key。

## 电脑接收端

Windows 端已实现独立 `FaceLiveLan.exe`，自动识别内网并启动接收，界面只有二维码、画面预览和虚拟摄像头启停，固定输出到 `xxx3`。默认端口 8767，如被占用则自动选取空闲端口。使用与打包见 [局域网接收端](22-局域网接收端.md)。以下保留手机与电脑之间的协议说明。

## 局域网接收协议

与远程服务器完全相同的 `direct-1` 协议，手机端代码不用区分：

1. HTTPS，自签名证书；证书 SHA‑256 指纹放进 `RGK1` Key（复用 `rgpu` 现有的证书 / Key 生成代码）。
2. `GET /health`（`Authorization: Bearer <口令>`）返回：
   ```json
   {"protocol": "direct-1", "features": ["lan-receiver"], "busy": false}
   ```
   `busy` 为 true 时手机提示“已经连着另一台手机”。口令错误返回 401。
3. `GET /stream` 升级 WebSocket，手机先发
   `{"type":"start","protocol":"direct-1","role":"source","video":{"width":720,"height":1280,"fps":30,"bitrate_kbps":6000}}`，
   接收端回 `{"type":"ready","protocol":"direct-1"}`（或 `{"type":"error","message":"…"}`）。
   需要接受最大 **1920×1080**（竖屏 1080×1920）。
4. 之后手机持续发送二进制 `RGV1` 帧（`!4sqHH` 头 + H.264 Annex‑B，关键帧带 SPS/PPS），以及每秒一次
   `{"type":"ping","time":…}`，接收端原样回 `{"type":"pong","time":…}`（手机用来显示网络延迟）。
5. 接收端解码后写入 FaceLive Camera 虚拟摄像头（复用 `FrameSink`），同时提供预览。
6. 界面：显示二维码（包含本机所有局域网 IPv4 地址）、刷新 Key、端口、Windows 防火墙一键放行。
