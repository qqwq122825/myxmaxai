# 0.4.0：手机推流，电脑接收

新增“中转”用法：**手机只推送摄像头画面，服务器换脸后把结果转发给电脑**，电脑不采集、不上传，只把结果写入虚拟摄像头给直播伴侣。

```
手机 AI魔颜 App（推流端） ──▶ 服务器（换脸） ──▶ 电脑本地端（接收端） ──▶ FaceLive Camera ──▶ 直播伴侣
```

## 操作

1. **服务器**：运行 `RemoteGpuServer.exe`，点“启动接收”，点“复制 Key”。
2. **电脑**：运行 `RemoteGpuLocal.exe`，填服务器地址和 Key，“工作模式”选 **只接收（手机推流）**，“画面尺寸”选直播用的尺寸，点“启动接收”，再“开启虚拟摄像头”。
3. **手机**：AI魔颜 App 填同一个服务器地址和 Key，点“连接”。
4. **服务器**：收到手机画面后，换脸软件输入选 Camera #2，选择结果窗口、“预览结果”，再“开始回传”。结果会发到电脑，不会发回手机。

电脑和手机先连哪个都可以。

## 规则

- 服务器同时接受 **1 台推流设备 + 1 台接收端**。第二台推流设备或第二个接收端会被拒绝，并提示“已有……连接”。
- 原来的“电脑推流并接收结果”（不选只接收模式）仍按旧方式工作，会同时占用这两个位置。
- 手机掉线重连：电脑保持连接，服务器的回传开关保持开启；手机重新连上后画面自动恢复。手机改了分辨率时，服务器会停止旧的结果采集，需要重新“预览结果”后回传。
- 电脑端的“接收帧率”是服务器转发来的结果帧率；“发送帧率”在此模式下为空。
- 手机连接时会检查服务器是否支持本功能；0.3.x 服务器会提示“服务器版本过旧”。需要先更新服务器，再用手机推流。

## 同时修复：偶发闪退

0.3.2 起，同一帧画面会同时交给编码线程和预览 / 虚拟摄像头线程转换格式，偶发进程崩溃（Segmentation fault，自动化测试约 1/4 概率出现）。0.4.0 让这两处转换依次进行（`rgpu/framelock.py`），连续多轮完整测试不再出现。

## 测试

`tests/test_relay.py`：手机推流 → 服务器原画回环 → 电脑收到；手机断开重连后电脑继续收到；第二台推流设备 / 第二个接收端被拒绝；旧服务器给出明确提示。
