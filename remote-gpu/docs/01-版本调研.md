# DeepLiveCam Pro 2.7 与 DFM 调研

核查日期：2026-11-02（Asia/Shanghai）。用户已明确目标是 **DeepLiveCam Pro 2.7**，单图和 DFM 两种方式都要试。

## 1. 结论与证据边界

Pro 2.7 的配套使用指南明确列出 DFM 支持，给出 `models\dfm` 目录和现代界面启动脚本 `onclick_run_qt6.bat`。指南将经典界面描述为简化的基础模型界面。因此，DFM 验证应从现代界面开始，而不是看到经典界面没有入口就判断整个版本不支持。[S01]

发布者相关性：指南博客的联系页与 Pro 官网支持页均列出 `@aidiscovery2045`，且指南与官网下载指向相同的 Hugging Face 发布仓库。这里将该指南作为关联发布渠道的说明资料，不把其中的性能描述当作我们的实测。[S02][S03][S04]

截至本次调研，未下载、解包或运行 2.7，也没有验证具体 DFM 的输入输出、遮罩和速度。方案可以按“Pro 2.7 支持 DFM”设计，但交付前必须使用固定版本安装包和目标 DFM 上机验收。

## 2. 必须区分的发行版

| 名称 / 渠道 | 本次可确认的内容 | 对方案的意义 |
|---|---|---|
| hacksider / Deep-Live-Cam 开源仓库 | 提供单图实时换脸项目 | 开源代码与付费衍生产品不能等同。[S05] |
| Deep-Live-Cam 2.7 Ultimate，deeplivecam.net | 官网发布 2.7 与后续版本；列出的 NVIDIA 配置有其自己的运行时要求 | 不把这些 CUDA 要求直接套在 Pro 2.7 上。[S06][S07] |
| **DeepLiveCam Pro 2.7** | 关联指南明确介绍 DFM 和现代界面入口；Pro 官网确认其与 Ultimate 为不同产品 | 本方案的主要换脸软件。[S01][S08] |
| DeepLiveCam Plus | 该分支发布者也明确介绍 DFM 与虚拟摄像头输出 | 证明其他分支亦存在这些能力，但不能用 Plus 的模型目录和界面替代 Pro 的说明。[S09] |
| DeepFaceLive | 官方仓库明确支持训练好的 DFM 模型 | 作为外部桥接的备选引擎，首版不强制再装一套。[S10] |

修正此前判断：不能笼统说“DeepLiveCam 只能单图，DFM 必须另接 DeepFaceLive”；应以具体发行版为准。

## 3. 安装包与运行时固定

Pro 官网下载渠道的压缩包会更新。官网新闻已有比 2.7 更新的 Classic / Standard 版本，不能只依据文章标题、压缩包文件名或 `main` 下载地址确定版本。[S04][S11]

部署时记录：

1. 原始下载页面、完整版本号、发布时间、实际包名与 SHA-256。
2. 使用现代界面加载 DFM 的截图与实际启动脚本。
3. 单图模型、DFM、遮罩、人脸增强模型的文件名和哈希。
4. NVIDIA 驱动、软件自带 CUDA / cuDNN / ONNX Runtime 或其他推理运行时的实际版本。
5. 输入设备、输出设备的精确名称与 DirectShow 设备标识。

不能因为 Ultimate 网页要求 CUDA 13，就给 Pro 2.7 的整合包额外覆盖安装 CUDA 13；先检查包内运行时及发布者要求。

V100S 属于旧 Volta 架构，CUDA 13 移除了针对这些架构的离线编译和库支持；旧 CUDA 构建的应用并不因此全部失效。其是否能运行某个 Pro 包，需要逐项验证，不能仅凭显存大小判断。[S12]

## 4. 不修改换脸软件的前提

- **输入：**换脸软件能够枚举并读取远程端的虚拟摄像头。
- **输出：**优先读取软件自带输出摄像头；具体 Pro 2.7 包的输出能力需验证，当前 Pro 网站展示的输出功能不等于旧包每项功能都相同。[S13]
- **备选：**若该包无可用输出摄像头，则采集独立预览窗口；验证窗口最小化、远程桌面断开后的行为。Ultimate 的窗口投影资料不作为 Pro 的功能证明。
- **控制：**本次未确认 Pro 2.7 有公开稳定的远程控制 API。首版在远程桌面中手动选照片 / DFM 和参数，不编造 API，也不许诺自动调参。

只有后续需要自动切模型、软件内部帧时间戳、直接 GPU 纹理交换等能力时，再评估发布者提供的接口或源码级适配。
