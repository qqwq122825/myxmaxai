# 0.3.0：独立双端与窗口结果回传

这次实现的是视频桥接软件，不修改或内置 DeepLiveCam Pro。支持 720p 横屏 / 竖屏、H.264 软件编码、TLS 单 TCP 端口。音频、1080p、NVENC 媒体编码、自动重连不在本次范围内。

## 服务器端：RemoteGpuServer.exe

1. 完整解压发布包，运行 `RemoteGpuServer.exe` 或 `启动远程端.cmd`。界面只包含服务器配置。
2. Key 和 TLS 证书在本机自动准备；首次启动自动识别公网出口 IP。检测失败可点“重新识别”，也可直接填平台提供的 IP / 域名。
3. **自动检测的出口 IP 不一定等于平台对外入口。** 有平台端口映射时，以平台给出的入口地址和公网端口为准。监听端口默认 8766。两者可以不同。
4. IP 和公网端口有效后，配对码自动显示，**无需先监听才能复制**。点“复制连接配置”，带入地址、Key 和证书指纹。
5. 在平台开放 / 映射 TCP 端口；Windows 防火墙规则可用管理员 PowerShell 运行 `deploy\开放直连端口.ps1 -Port 8766` 添加。该规则针对新版服务器 EXE，不关闭系统防火墙。
6. 点击“启动接收”。连接设置自动收起，留出结果采集空间。
7. 在换脸软件中选择 `FaceLive Camera #2` 作为输入。服务器界面默认将接收画面提供给此虚拟摄像头，可单独关闭该输出开关。
8. 换脸软件打开独立结果窗口。左侧“结果来源”选“独立窗口”，刷新并选择正确窗口（显示 PID / HWND 防止同名误选）。
9. 默认“Windows 图形采集”；如失败，可试“兼容采集 · PrintWindow”。选择后点“预览结果”，右侧结果画面确认无误再点“开始回传”。
10. “停止回传”保留原画接收和结果预览；“停止结果采集”释放结果窗口 / 摄像头。“停止服务”停止网络，预览和虚拟摄像头可单独控制。退出软件释放全部资源。

如果软件已经提供结果虚拟摄像头，可直接选“结果虚拟摄像头”，避免窗口边框和裁切问题。不要把输入的 Camera #2 再选作结果摄像头。

## 本地端：RemoteGpuLocal.exe

1. 运行 `RemoteGpuLocal.exe` 或 `启动本地端.cmd`，只包含本地设置。
2. 先复制服务器完整的 RGPU1 配对码，点击“导入连接配置”。地址、Key、证书指纹会自动填入。
3. 也可手填地址和 Key；自签名 TLS 的服务器还需在“高级设置”填写服务器证书 SHA-256 指纹。程序不会因为手填而跳过身份验证。
4. 选择 YY开播 / 摄像头 / 测试画面，先“仅本地预览”确认输入，再“启动推送”。开始推送会先停止同设备的本地独立预览，避免重复占用。
5. 等待服务器采集并开启回传。界面会区分等待结果和正在回传；等待期间原画持续推送。
6. 点击“开启虚拟摄像头”。在直播伴侣中选择 `FaceLive Camera`。该开关独立于推送；无结果超过约一秒时写入黑画面，避免无限保留旧画面。

本地不需要公网 IP、入站端口、家庭路由器映射或 Tailscale。本地端与服务器端分别保存非敏感表单配置；本地 Key 不自动写入配置文件，重新启动后可重新导入。

## 驱动和换脸软件

首次使用虚拟摄像头时，需在两台电脑分别安装包内的驱动。先关闭使用 FaceLive 摄像头的程序，在解压目录以管理员 PowerShell 运行：

```powershell
.\deploy\install-driver.ps1
```

该驱动注册 `FaceLive Camera` 和 `FaceLive Camera #2`。已安装时通常不需要重复安装；它与原 FaceLive 项目共用驱动，不能同时让两个发送程序写同一个通道。输入端安装好后重新打开换脸软件，输出端安装好后重新打开直播伴侣。

DeepLiveCam Pro、DFM 与其他模型仍由用户在服务器另外准备。本软件不知道窗口中的内容是否已经完成换脸，需要在“预览结果”中自行确认。

## 窗口采集边界

- 按明确选择的窗口句柄及 PID 采集，关闭 / 被替换后要求重新选择，不跟随任意同名窗口。
- 保持所选结果窗口非最小化。窗口最小化、关闭或无法返回画面时停止结果回传，原画接收可继续。
- “裁切窗口边缘”填写原始捕获画面的左、上、右、下像素，默认全部为 0。调整后重新“预览结果”。画面按原比例缩放补黑边，不拉伸。
- Windows 图形采集适合图形窗口；PrintWindow 兼容方式仍取决于目标软件是否提供可捕获内容。黑屏时需在实际软件中换采集方式或改用结果虚拟摄像头。
- 原生采集运行在子进程；无首帧或调用卡住时可终止该进程，避免整个界面一起卡死。不会回退为捕获整个桌面。
- Windows Server 2022 / RDP 断开后的采集行为仍须在租用机器上验证，不建议未经测试就断开正在运行的桌面会话。

## 先验证网络

本地选择“测试画面”并推送；服务器选择“原画回环（测试网络）”，点“预览结果”，再“开始回传”。这只验证视频链路，不执行换脸。确认双向画面和流量后，接入 Camera #2、真实换脸软件与结果窗口。

源码的旧 WebRTC 与 direct-agent 命令保留用于诊断；新的独立启停功能在 0.3.0 图形界面的服务器桥接中提供。两端均建议更新至 0.3.0。
