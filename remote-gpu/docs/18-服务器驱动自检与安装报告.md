# 0.4.7：修复服务器驱动误拦截与安装报告

## 为什么 0.4.6 一直提示不一致

0.4.6 的服务器端在读回自检前比较了「包内 DLL」和「系统注册的 DLL」的 SHA256。两者不同就停止写入，因此手机画面可以正常进入服务器、接收达到 30 FPS，但 DeepFaceLive 只看见驱动的绿色等待图。

文件不同不等于驱动一定不可用。0.4.7 改为：记录差异，继续真实写入和读回自检；缺少设备、无法打开、读不到正确画面仍会显示实际检查结果。此更改不把所有旧驱动一概判为正常，也不修改 DeepFaceLive。

## 先更新服务器

1. 关闭旧桥接服务器，使用针对完整 0.4.6 的增量包，合并覆盖原 RemoteGpu 目录。
2. 启动 **RemoteGpuServer.exe**，确认标题是 **0.4.7**。
3. 点击「启动输入虚拟摄像头并自检」，再让手机推流。核对左侧收到画面和自检结果。
4. 自检完成释放读取端后，在 DeepFaceLive 中重开 FaceLive Camera #2，并选对应的 1080×1920 / 720×1280。已经打开的捕获设备可能继续保留旧的连接尺寸，不能只看分辨率下拉框。
5. 手机到服务器的画面正常、DeepFaceLive 仍是绿色等待图时，查看输入自检和运行日志；不要把它理解成需要调高「500 ms」。

本地 0.4.6 与服务器 0.4.7 使用相同传输协议，可以继续连接。服务器修复包只更新服务器入口、安装脚本、驱动文件和本文，不必重传大运行库。

## 需要安装驱动时

先关闭 DeepFaceLive、Pro、桥接端和所有摄像头检查器。进入 RemoteGpu\deploy，**右键 install-driver.cmd → 以管理员身份运行**。

新脚本会：

- 检查两份源 DLL 是否存在、PE 结构和 32/64 位架构是否正确。
- 在替换前检查目标文件是否可写；先备份有变化的旧 DLL。相同文件跳过复制。
- 等待 64 位和 32 位 regsvr32 各自退出，记录实际退出码。
- 核对两个摄像头、两个注册表视图的实际注册路径和 SHA256；注册命令返回 0 但路径错误也会报告失败。
- 保存成功或失败报告；CMD 窗口暂停，便于看到报错，不会一闪而过。
- 通过 .NET 计算 SHA256，避免依赖 Get-FileHash 命令自动加载。

报告位置：

```text
%LOCALAPPDATA%\FaceLiveRemoteGpu\reports\driver-install-日期时间.json
```

`status: verified` 表示安装路径和哈希校验通过，仍需重开程序并做实际摄像头读回自检；不等于已验证所有换脸软件。

若依然失败，把新生成的 `driver-install-*.json` 发来。报告记录包来源、注册前后路径、文件哈希、管理员状态、注册退出码和具体异常，能区别权限、文件占用、注册失败和从错误目录运行。

只诊断、不安装、不注册（无须管理员）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\install-driver.ps1 -DiagnoseOnly
```

## 本次验证范围

Windows PowerShell 5.1 的 64/32 位只读诊断、损坏 DLL 拒绝、模拟注册返回 0 但实际注册路径不匹配的失败报告均已测试；测试没有注册或替换本机真实驱动。Tk 自检流程已复现「文件哈希不同但可写入读回」并通过。远程服务器实际安装是否成功，需以该机新报告和读回画面为准。
