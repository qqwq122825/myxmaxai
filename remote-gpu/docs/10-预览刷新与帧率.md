# 0.3.2：预览流畅度与真实显示帧率

0.3.1 的“发送帧率 30 FPS”代表编码发送统计，界面却使用 100 毫秒的刷新定时器，所以预览最多约 10 FPS。YY 原窗口会明显更流畅，这是界面实现问题，不能据此认定网络只有 10 FPS。

0.3.2 修复了预览刷新：

- 按 60 Hz 的检查节奏绘制最新视频帧，扣除本轮处理时间；没有新帧就不重复绘制。
- 复用 Tk 图像资源，保留最新一帧，不排队播放积压图像。
- 仅预览的输出线程由新帧事件唤醒，避免再套一个独立 30 Hz 采样定时器丢帧。
- 两块画面下方分别显示“预览显示 x FPS”。这统计每秒提交到 Tk 图像的新视频帧，区别于网络发送 / 回传 FPS；窗口缩放导致的重复重画不会增加该计数。
- 未收到任何回传帧时，保留等待文字；断流后清除旧画面一次，不把反复显示同一张图统计成新帧。

本机 720×1280、双画面动态合成图对照：复现旧的 10 Hz 检查条件时，两块预览各约 10 FPS；修复后源约 29.98 FPS，两块预览约 29.98 / 29.78 FPS。这是桌面 UI 更新测试，不是实际显示器扫描、远程换脸速度或端到端延迟测试。

## 怎么判断是哪一段慢

| 位置 | 指标含义 |
|---|---|
| 每块画面下方“预览显示” | 本程序实际向界面提交新视频图像的帧率 |
| “发送帧率” / “接收帧率” | 网络视频发送或接收处理的帧率 |
| “回传帧率” | 已处理的返回视频帧率；等待服务器开启回传时应为 0 |
| “网络往返 RTT” | 控制消息的往返时间，不是完整视频延迟 |

截图中如“发送 30，回传 0”，说明原画在上传，服务器尚未返回结果。服务器需要选择结果来源，成功“预览结果”后点击“开始回传”；先用“原画回环”验证也可以。

本次没有变更网络协议或 Key。先更新本地端即可修复本地预览；服务器 0.3.1 可继续连接，服务器也更新后其预览会获得同样修复。不需要重新生成 Key。

## 可复现测试

发布包提供两路合成图界面测试，不用摄像头、不联网、不写虚拟摄像头：

```powershell
.\RemoteGpuLocal.exe preview-benchmark --portrait --seconds 5 --report preview-result.json
```

测试会打开正常尺寸的界面并在结束后关闭。报告中的预览 FPS 来自实际 Tk 图像更新计数，包含绘制间隔统计；测量结果随电脑负载、窗口尺寸和桌面会话变化。
