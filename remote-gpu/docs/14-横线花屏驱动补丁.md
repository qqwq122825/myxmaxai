# Camera #2 横线花屏补丁

用户已确认竖屏正常。此次处理 Pro 打开 Camera #2 后画面可动、但出现密集横线的问题。

## 驱动缺陷与修正

0.4.2 的驱动允许多种尺寸，但 `IAMStreamConfig::SetFormat` 设置完成后，
`IPin::EnumMediaTypes` 仍可能返回原先首选尺寸和其他类型，导致后续建图采用另一格式。
现已在原生回归测试中复现：设置 960×540 后，0.4.2 DLL 枚举得到的首个格式并不是 960×540。

修正后，一旦应用设置格式，后续连接只提供同一尺寸、位深、子类型和帧间隔；
`GetStreamCaps` 继续负责列出可选能力。不同格式的连接请求会明确拒绝，避免解释错帧。
该行为与 [Microsoft SetFormat 接口要求](https://learn.microsoft.com/en-us/windows/win32/api/strmif/nf-strmif-iamstreamconfig-setformat)一致。

同时修复横竖比例不一致时，缩放边界的一列像素可能越到下一行的问题，并补上共享内存映射释放。

## 小补丁更新方式

此驱动补丁适用于已有完整 **0.4.2** 的 RemoteGpu 文件夹，不含 EXE、运行库、模型或密钥。
覆盖后原程序标题仍可能显示 **0.4.2**，这是正常的。

1. 停止 Pro 换脸，关闭 Pro、服务器桥接程序、独立摄像头检查器。
2. 解压补丁，将其中的 RemoteGpu 文件夹与服务器原 RemoteGpu 文件夹合并覆盖。
3. 在该目录打开管理员 PowerShell，执行：

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\deploy\install-driver.ps1
   ```

4. 重新打开桥接程序，启动输入虚拟摄像头并自检，保持本地原画推送。
5. 重启 Pro、重新选择 FaceLive Camera #2，检查横线是否消失。

必须重新安装驱动；只覆盖 VirtualCam 目录不能更新 ProgramData 中实际加载的 DLL。
安装脚本会保留被替换的旧 DLL 备份。

## 验证

- 旧 0.4.2 DLL 已复现设置格式与后续枚举格式不同；新驱动通过回归测试。
- 像素测试使用生产代码，覆盖横屏、竖屏、横竖转换、720p→540p、RGB24/RGB32、紧凑及带间隙的输入行，共 20 组组合。
- 同时验证共享内存→生产 FillBuffer→IMediaSample 的真实字节数、像素内容及缓冲区边界。
- 测试只使用合成图像和未注册的测试通道，不打开用户物理摄像头。
- 仍需服务器上的 Pro 实际复测；不能仅凭驱动测试判断 Pro 全链路已经修好。
