# 租机、实施阶段与验收

当前已有可执行双端原型。4090 服务器已开好，程序与环境检测可以运行；组网和换脸软件仍待配置。本文件是后续执行清单。

用户拟选镜像为 Windows-nvidia 2022 64 位虚机（CUDA 12.8、40 GB 磁盘）与 4090 24 GB。先通过原型“保存环境检测”确认实际系统和 GPU，再验证 Pro 2.7。不能把本机回环通过当作 Server 2022 兼容性已通过。

## 1. 推荐先租什么

建议先按小时租距离近的 **Windows 11 桌面 GPU 电脑**。先用 RTX 4090 24 GB 作为对照测试机，验证 Pro 2.7 单图与目标 DFM 后，再评估是否可用更低配置降成本。24 GB 是容量信息，不是 30 FPS 保证。[NVIDIA RTX 4090 规格](https://www.nvidia.com/en-us/geforce/graphics-cards/40-series/rtx-4090/)

工程配置起点：8 个可用 vCPU、32 GB 内存、100 GB 以上持久化磁盘。它们是为了兼顾桌面软件、编解码、模型文件和调试的建议，不是 Pro 2.7 发布者公布的最低配置。

不把 V100S 作为首次默认机型：它可能能跑兼容构建，但旧架构、桌面图形环境和运行时适配会增加验证项。我们的首轮重点是把整个链路跑通，再比较价格 / 性能。

| 必须询问 / 实测的条件 | 原因 |
|---|---|
| 能否安装完整 Windows 11 并持续保留桌面会话 | 目标软件和摄像头桥接按 Windows 桌面方式设计 |
| 是否有管理员权限，允许注册 DirectShow 虚拟摄像头 | 远程需要专用输入设备 |
| GPU 是否真实可用，能否访问 NVENC / NVDEC | 有 CUDA 不等于硬件视频编码器可用 |
| 断开远程桌面后 GPU、摄像头、结果窗口是否继续输出 | 登录会话变化可能导致显示 / 采集路径改变 |
| 是否有足够独立或实测稳定的上下行 | 峰值共享带宽不等于直播容量 |
| UDP 是否允许，能否安装组网工具，必要时如何使用 TURN | 只有 HTTP / SSH TCP 映射可能无法直连媒体 |
| 是否允许持久化磁盘与快照，重启是否更换机器身份 | 影响软件配置、模型和授权 |
| Windows、出站流量、IP、中继与磁盘如何收费 | GPU 小时价不是全部费用 |

Pro 官网说明授权首次使用会绑定一台电脑，换机 / 重装有重新激活流程。租用机器可能变化，应先确认该版本对云电脑和迁移的授权处理，试用完成前不急于在临时机器绑定长期授权。[Pro 支持说明](https://deeplivecam.pro/en/support)

## 2. 分阶段实施

### 阶段 A：固定 Pro 2.7 并验证软件 I/O

在目标 Windows GPU 电脑上验证：

- 安装包确为 Pro 2.7，记录来源、SHA-256 和实际运行时。
- 现代界面启动正常；一张照片换脸和一份已授权 DFM 都能处理测试视频。
- 读取虚拟输入摄像头正常，记录设备 ID。
- 自带输出摄像头是否可供外部程序连续读取；没有则验证独立结果窗口采集。
- 远程桌面断开、重连之后仍连续出图。

产物：版本清单、设备清单、单图与 DFM 负载基线。阶段 A 不通过时先解决软件 / 桌面问题，不用网络复杂度掩盖问题。

### 阶段 B：不换脸的网络回环

实现本地和远程传输原型，上传视频后直接回传。确认 WebRTC 连接、编码器、实际直连 / 中继路径、原始帧队列和断线恢复。

产物：720p 双向码率、CPU / GPU 编码占用、P50 / P95 延迟与稳定性记录。

### 阶段 C：接入外部换脸软件

远程创建独立的 `Remote GPU Input`，让 Pro 2.7 从该设备读取；Agent 采集结果再回传。分别验证单图基础、单图加增强、DFM、DFM 加增强。

产物：四种模式的有效帧率、总延迟、画质对比与资源占用。模型选择和参数先通过远程桌面操作。

### 阶段 D：本地虚拟摄像头与直播伴侣

本地回传帧输出到 `FaceLive Camera`，直播伴侣选择该设备并验证横屏 / 竖屏、镜像、色彩与裁剪。配置麦克风音频延迟，同时运行平台推流测试网络余量。

产物：实际直播录制、音画同步测量、断线备用画面与恢复验证。

### 阶段 E：独立打包与主项目整合

先打包单独客户端 / Agent、环境检测、输入虚拟摄像头安装和使用说明。通过稳定性测试后，再决定是否在现有 WPF 主界面加入“自租 GPU”后端。

主项目整合涉及现有 Xmax 会话、采集接口和虚拟摄像头单写入者，需作为独立变更实现；当前原型已经独立打包，尚未接入主项目界面。

## 3. 建议验收标准

以下是项目目标，不是租机前已保证的性能：

| 项目 | 判定方法 |
|---|---|
| 双向媒体 | 真摄像头上传，处理结果回传，本地虚拟摄像头可被直播伴侣读取 |
| 两种模型 | 固定 Pro 2.7 在同一台机器完成单图和目标 DFM 测试 |
| 免改第三方软件 | 不修改其程序文件，依靠输入 / 输出设备或独立窗口完成桥接 |
| 720p 基础单图 | 先以有效处理 / 返回 ≥25 FPS 为目标，分别记录采集与虚拟输出帧率 |
| DFM | 记录实际结果，按目标模型与遮罩 / 增强组合评估，不能用基础单图 FPS 替代 |
| 延迟 | 先以 P50 ≤300 ms、P95 ≤450 ms 为目标；用画面实测，不以 ping 或软件 FPS 代替 |
| 持续运行 | 实际直播时段连续至少 60 分钟，不出现越来越大的帧队列或明显内存增长 |
| 故障恢复 | 模拟断网 / 远端软件停止，显示故障并切换备用画面，恢复后不补播旧帧 |
| 设备隔离 | 输入不接到输出形成回路，FaceLive Camera 同时只有一个写入者 |
| 音画同步 | 拍手和口型测试，记录音频延迟设置及网络波动后的效果 |
