# 0.1.1 双端原型使用说明

这是旧 WebRTC / Tailscale 连接方式的说明。0.2.0 默认采用免账号公网直连，操作请看 [新版说明](07-免账号公网直连.md)。本地 YY 预览和虚拟摄像头桥接的操作仍然适用。

本版提供同一套 Windows 程序的本地端和远程端，不修改 DeepLiveCam Pro / DeepFaceLive。**先验证回环，再接换脸软件。**

## 1. 当前具备的能力

- 中文图形界面，两端共用 `RemoteGpu.exe`。
- “仅本地预览”可在没有服务器、地址、密钥和 Tailscale 时验证 YY / 真实摄像头，不上传、不写虚拟摄像头。
- DirectShow 摄像头枚举与稳定设备 ID；输入可以是真摄像头或测试图。
- WebRTC 双向 H.264 视频，连接密钥校验，数据通道 RTT、码率、返回 FPS 统计。
- 最多 720p / 30 FPS，支持 1280×720、720×1280；也可先用 640×360 / 20 FPS。
- 远程“回环测试”和“换脸桥接”两种模式。
- 远程输入写到 `FaceLive Camera #2`，本地结果写到 `FaceLive Camera`。
- 原始帧队列有界、断流约 1 秒后切黑、停止释放会话与输出。
- 环境检测、虚拟摄像头安装和仅允许指定对端 IP 的防火墙脚本。

当前限制：软件 H.264 编解码；没有启用 NVENC，没有自动切换模型、自动重连、预览窗口直接采集、音频传输或音频延迟模块。Pro 中的掉脸处理仍由 Pro 自己负责。统计的 RTT 是数据通道往返时间，不是总视频延迟；程序也不宣称能识别实际直连 / 中继路径。

## 2. 租用的 Server 2022 先检查什么

你提供的镜像信息：4090 24 GB、Windows-nvidia 2022 64 位虚机、CUDA 12.8、40 GB 系统盘。

1. 用远程桌面进入后，先把本程序完整文件夹放到持久化磁盘。
2. 点“保存环境检测”，查看界面提示的完整路径：系统、GPU / 显存 / 驱动、空余磁盘、摄像头、Tailscale 与编码器探测。打包程序默认保存到 `%LOCALAPPDATA%\FaceLiveRemoteGpu\reports\environment-日期时间.json`，不依赖启动位置。
3. 先保留镜像 CUDA 12.8，不覆盖安装其他 CUDA。Pro 整合包的实际运行时单独确认。
4. 40 GB 是系统盘规划，不是显存。需要预留 Windows 更新、软件解压、模型和临时文件空间；空间紧时先扩容或另挂持久化数据盘。
5. Pro 官网主要列出桌面 Windows 版本；Server 2022 上的驱动、虚拟摄像头与软件兼容性要实测。

## 3. 两台机器组网

**本地无需单独购买内网穿透、申请公网 IP 或做路由器端口映射。** 本原型两端加入同一 Tailscale 网络，再用同一个双向 WebRTC 会话上传和回传。Tailscale 本身提供组网、NAT 穿透与必要的中继退路；“不需要额外穿透工具”不等于网络没有穿透 / 中继机制。允许程序的系统防火墙流量仍然必要。[官方防火墙说明](https://tailscale.com/docs/reference/faq/firewall-ports)、[连接类型说明](https://tailscale.com/docs/reference/connection-types)。

首版建议两端安装并登录同一个 Tailscale 网络。官方入口：[Tailscale 下载](https://tailscale.com/download)。本程序不会自动安装或登录。

两端应各得到一个 `100.x.x.x` 地址。远程端点击“检测 Tailscale IP”可填入监听地址；`127.0.0.1` 只能本机访问，不能留给另一台电脑连接。

先检查两端可达，并用 `tailscale ping 对方IP` 查看是否 direct。走中继也可能连接成功，但需要实测延迟和吞吐。程序默认不联系公共 STUN，也不自动部署 TURN。

如果防火墙拦截，在**两端管理员 PowerShell** 中分别运行（用对方真实的 Tailscale IP 替换示例）：

```powershell
Set-Location 'D:\RemoteGpu'
.\deploy\configure-firewall.ps1 -PeerAddress '100.80.20.30'
```

此脚本仅给本程序添加 TCP 8765 与动态 UDP 媒体的入站规则，并限制对方 IP。不会关闭防火墙。如果平台另有安全组 / 网络限制，也要验证该平台允许此流量。

GUI 只允许绑定具体的局域网 / Tailscale IP，不绑定 `0.0.0.0`。公网信令必须用 HTTPS，命令行支持 `--cert` / `--key`。自定义 STUN / TURN 可用 `--ice-config` 传入含 `iceServers` 的 JSON，尚未做外网 TURN 实测。

## 4. 第一步：两机回环，不开换脸软件

### 没有服务器时：先预览 YY

1. 打开 YY 开播，准备好要输出的画面。
2. 运行发布包根目录的 `预览YY画面.cmd`，会自动选择 YY 并开始竖屏本地预览。
3. 也可以运行“启动本地端”，刷新摄像头后选择“YY开播”，选好横 / 竖屏，点“仅本地预览”。
4. 此时地址与密钥可以留空；不启动远程会话，不上传画面，也不占用输出虚拟摄像头。
5. 改分辨率先停止，再选择新档位并预览。YY 按请求尺寸输出；像素格式自动协商，不强制 I420。
6. 不要在 YY 输入中再选择 FaceLive Camera，防止形成画面回路。

设备名称与方法沿用现有项目的 DirectShow → YY 开播方案。本原型通过 PyAV 的 FFmpeg DirectShow 输入读取相同的 `yyanchorvcam` 设备，而不是录制整个桌面或选择 YYAnchor 进程。预览保持比例，不额外镜像或上下翻转。

### 远程 4090 电脑

1. 解压 / 复制完整发布文件夹，运行 `启动远程端.cmd`。
2. 点击“检测 Tailscale IP”，确认监听地址为远程的 `100.x.x.x`。
3. 保持“回环测试（先验证网络）”模式。
4. 点“复制连接密钥”，只传给你自己的本地端。
5. 点“启动当前端”。

### 本地电脑

1. 运行 `启动本地端.cmd`。
2. 地址填 `http://远程TailscaleIP:8765`，粘贴连接密钥。
3. 输入先选“测试图（不采集摄像头）”，选 1280×720 / 30 FPS、4000 Kbps。
4. **第一次先取消勾选“输出到 FaceLive Camera”**，这样可不安装驱动直接验证回传预览。
5. 点“启动当前端”。应看到移动测试图和时间，回传 FPS、实际上下行码率逐渐出现。
6. 停止后刷新并选择真摄像头，再测试一次。

密钥只保留在当前 GUI 内存中，重开远程 GUI 会重新生成，需要重新复制。命令行远程端可保存到 `server.access-token`；不要把该文件发给别人或提交到仓库。

## 5. 第二步：安装虚拟摄像头

关闭原 FaceLive 程序及使用相关摄像头的软件。在两端分别用**管理员 PowerShell**执行：

```powershell
Set-Location 'D:\RemoteGpu'
.\deploy\install-driver.ps1
```

会注册：

| 设备 | 通道 | 本方案用途 |
|---|---:|---|
| FaceLive Camera | 0 | 本地接收结果，供直播伴侣读取 |
| FaceLive Camera #2 | 1 | 远程接收原画面，供 Pro 读取 |

安装脚本复用现有 FaceLive 驱动及其多摄像头能力。它会注册到 `%ProgramData%\FaceLive\VirtualCam`，与原 FaceLive 程序共享驱动；不是修改 Pro。卸载会影响原 FaceLive，故不在程序退出时自动卸载。

本地远程客户端与原 FaceLive 程序不能同时写通道 0。远程如果 Pro 自己也用 UnityCapture，请确保其结果输出使用别的通道，不能占用 `FaceLive Camera #2`。

## 6. 第三步：连接 Pro 2.7

### 在远程 4090 电脑操作

1. 安装并确认实际是 DeepLiveCam Pro 2.7；本发布包不包含该软件或模型。
2. 使用 `onclick_run_qt6.bat` 启动现代界面。试单图时选照片；试 DFM 时按该包说明放入 `models\dfm` 并选择模型。
3. 输入摄像头选择 **FaceLive Camera #2**，将画面设为和本地发送档位一致，如 1280×720。
4. 开启 Pro 的结果虚拟摄像头。必须是和输入不同的设备，并能被 DirectShow 读取。
5. 回到本程序远程端，停止旧回环，选择“换脸桥接”，刷新摄像头并选择 **Pro 的结果摄像头**，再启动。

若 Pro 2.7 在此镜像上没有可用的结果虚拟摄像头，可使用 OBS 窗口采集其独立结果窗口，并启动 OBS Virtual Camera；远程端选择 OBS Virtual Camera 作为结果摄像头。该备选的窗口可采集性和断开远程桌面后的行为仍需实测。本原型自身尚未直接实现 Windows Graphics Capture。

### 在本地操作

1. 选择真摄像头、远程地址与密钥，勾选输出 FaceLive Camera，启动连接。
2. 抖音直播伴侣选择 **FaceLive Camera**，不要选真实摄像头或 `FaceLive Camera #2`。
3. 在直播伴侣打开设备后，本程序“摄像头写入”计数应增加。首次未打开消费端时可能只有回传预览；该计数表示共享内存写入成功，不证明直播软件已显示或仍在消费。
4. 麦克风仍在本地。视频走远程后有额外延迟，本版不处理音频；按实测使用直播软件可用的音频延迟功能或 OBS 完成音画同步。

## 7. Server 2022 的必要实测

- Pro 单图 / DFM 是否真的由 4090 加速，不能只看系统中安装了 CUDA。
- Pro 输入与结果设备能否同时持续打开，是否发生设备独占。
- 断开远程桌面（不注销账号）后，连续采集和换脸是否仍运行。
- 如果窗口采集依赖显示会话，最小化 / 断开远程桌面是否变黑。
- 同时启动直播伴侣推流后，家庭上行是否仍有余量。

## 8. 源码运行与本机自检

源码需要 Python 3.12 x64。发布包自带运行时，使用 EXE 不需要另外安装 Python。

```powershell
Set-Location 'D:\ai直播换脸\remote-gpu'
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe remote_gpu.py gui
.\.venv\Scripts\python.exe remote_gpu.py selftest --report reports\selftest.json
.\.venv\Scripts\python.exe remote_gpu.py probe --camera yy --width 720 --height 1280 --seconds 5
```

`selftest` 在本机创建真实 WebRTC / H.264 往返，不访问真摄像头、不连接远程服务器，也不执行换脸。不要将其 FPS 当作 4090 换脸 FPS 或公网表现。

开发测试与打包：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
.\deploy\build.ps1 -Python "$PWD\.venv\Scripts\python.exe"
```

## 9. 常见问题

| 表现 | 优先检查 |
|---|---|
| 地址连不上 | 是否填了远程 IP、远程是否启动、Tailscale 可达、TCP 8765 是否允许 |
| 连接成功但没有视频 | UDP、防火墙、摄像头输出、所选设备和分辨率；仅 HTTP 通不能证明媒体通 |
| 提示已有会话 | 在旧本地端停止；异常退出后等待远程超时释放，或停止再启动远程端 |
| 回环正常，桥接黑屏 | Pro 是否读取 #2、是否开启独立结果摄像头、是否误选输入当输出 |
| 预览有图但直播伴侣没图 | 安装驱动、选择 FaceLive Camera、关闭原 FaceLive 写入者、重新打开设备 |
| 图片变黑但连接仍在 | 默认超过约 1 秒没新帧会切黑，需检查来源；之后会因媒体超时停止会话 |
| 画面比例不对 | 本版保持比例并加黑边；先匹配采集与输出分辨率，不强制拉伸 |
| 摄像头停止后仍被占用 | 某些驱动阻塞退出；先关闭本程序再重开，不在后台无限重试 |

打包程序日志位于 `%LOCALAPPDATA%\FaceLiveRemoteGpu\reports\remote-gpu.log`，源码运行默认使用工作目录下的 `reports/`。环境报告包含设备与工作目录信息，分享前可按需去掉这些本机信息；连接密钥不会主动写入日志或环境报告。
