# 直播伴侣、镜像和 30 FPS（0.4.4）

后续确认：用户反馈是重复添加了两个摄像头素材，保留一路后已可用。0.4.5 已取消仅凭驱动哈希不同就阻止启动的限制；已正常使用时无需重新安装驱动。下面保留当时的诊断和按需更新方法。

## 本地直播伴侣显示 FaceLive Camera 不可用

本次本机诊断发现：

- 回传画面已经到达本地，网络接收计数不是虚拟摄像头读取计数。
- 已安装的本地输出驱动与新版 DLL 哈希不同；本机尚未注册 Camera #2。
- 直播伴侣 2026-11-02 19:10 的业务日志将旧 ID `foo:bar` 列入「被占用的设备列表」，对应场景内已存在的 FaceLive Camera 素材。再次添加另一摄像头素材时可能禁用这项。
- 本机通过 DirectShow 能读取 FaceLive Camera，720×1280；短时探测约 15.4 FPS，不能据此认定直播伴侣已正常显示。

更新步骤（本地电脑执行；服务器不需要重复更改已工作的输入设置）：

1. 关闭直播伴侣、旧桥接程序及摄像头检查器。
2. 将更新包内 RemoteGpu 文件夹合并覆盖原完整 0.4.2 目录。
3. 在 RemoteGpu 文件夹打开**管理员 PowerShell**：

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\deploy\install-driver.ps1
   ```

4. 启动新版本地端，连接服务器，确认右侧有回传，再开启虚拟摄像头。
5. 点击「检查输出摄像头」，核对真实画面及方向，检查完关闭检查器。
6. 重开直播伴侣。删除或重新选择旧 ID 的 FaceLive Camera 素材，添加普通摄像头素材并选 FaceLive Camera；同一场景仅保留一路。截图中的「手机摄像头」是直播伴侣自己的手机接入功能，本方案的手机视频由桥接接收端输出。

新版驱动使用每台设备独立的 `facelive:camera:{CLSID}`，替代旧版通用 `foo:bar`。更新后须重启读取软件、重新选择素材；仅覆盖压缩包并不会更新 ProgramData 中已注册的 DLL。

若检查器有画面、直播伴侣仍不可用，先检查重复素材/占用，再保留新的直播伴侣日志继续查。DirectShow 检查通过不等于直播伴侣端到端通过。本次没有自动修改直播伴侣场景或中断正在运行的桥接连接。

## 镜像

- 服务器「接收并提供换脸输入」→「输入画面左右镜像」：翻转服务器左侧预览和 Camera #2 的实际输入像素。手机端不用修改。
- 本地「接收与直播输出」→「直播输出左右镜像」：翻转右侧预览和 FaceLive Camera 的实际输出像素。
- 两端分别保存，运行中可切换；无需重新连接。不要同时在桥接、DeepFaceLive 和直播伴侣重复翻转。
- 自检彩色图保持固定方向，镜像开关仅作用于真实输入。镜像没有改变传输协议、分辨率或手机上传画面。

手机前置相机常常只镜像取景预览，推流数据方向可能与屏幕预览不同。用有文字的物体核对实际收到的画面，按需要只打开一处开关。

## DeepFaceLive 的 30 FPS

截图：摄像头 FPS 配置为 **25.00**，最终输出平均约 **24.9**；DFM 与融合模块的处理速度读数约 **28 FPS**，输出延迟为 **500 ms**。4090 型号和 3D 引擎占用不能保证整个链路持续 30 FPS。

先按以下顺序设置，每步观察 30 秒真实输出，避免一次修改多项：

1. 手机 App 采集、桥接传输设置为 30 FPS；先确认服务器接收稳定约 29–30。
2. DeepFaceLive 摄像头源：DirectShow、FaceLive Camera #2、720×1280，将 FPS 从 25 改为 **30**（或 0 自动）。不要用补帧或重复帧掩盖不足。
3. 视频输出「目标延迟」从 500 改为 **0–100 ms**，先试 50。它控制等待和缓冲，不会让模型算得更快；过低可能增加抖动，按网络和处理波动调整。
4. 保持检测器 YOLOv5、单人，检测器/标记器/DFM/融合器均选对应 GPU。截图中多个模块已经选 GPU，无须盲目重装 CUDA。
5. 若仍低于 30，先保持现有 416 对齐分辨率，临时将融合「色彩迁移 rct」改为 none 对照；这会影响颜色匹配。若没改善就恢复。再尝试较低对齐分辨率/较轻的 DFM 模型，逐项比较速度和质量，不能承诺原模型质量设置不变也能跑满。
6. 关闭不需要的多路大预览，保持独立 `DeepFaceLive output` 窗口可采集且不最小化。服务器桥接只采集结果窗口。
7. 最后检查：DeepFaceLive 最终输出、服务器回传、本地接收、输出摄像头检查器四处 FPS。每个模块顶部数字主要反映该模块处理耗时的倒数，不代表全链路有效帧率。

0.4.4 桥接输出改用固定时间基准安排写帧，减少 Windows 等待误差累积；处理跟不上时不补发积压帧。这项更改不加速 DeepFaceLive 模型本身。

GPU 使用率查看相应 Compute/CUDA/OpenCL 引擎或在服务器运行 `nvidia-smi`；单个「3D」图不能概括所有计算引擎。截图 CPU 55% 也不能排除单核/内存拷贝或 GPU 同步瓶颈。
